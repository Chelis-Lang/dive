# Source-owned pure safety disk role binding

Issue #221 / [ADR0075](../../../docs/decisions/0075-source-owned-pure-safety-role-admission.md)
extends the opt-in ordinary disk-seen route through the actual shared binder.
Resident behavior, fallible key/error transactions and all memory budgets remain
unchanged. This is partial F-031 support, not temporal, parallel-read, recovery,
durability, total-memory or family certification.

The original `declared-selection.json` carries all29 selected models. `before/`
retains145 actual primary/native observations with their original881b producer
and exact consumer fixture hashes; none is retagged as this implementation.
`development/` preserves setup/style/assertion/current-authority failures and the
stable pre-freeze inventory checks. `before-authorities/` retains previous current
hash maps and the original repository-dependent engine reader/index.

Current-source qualification and fresh native CLI/public API execution are in
progress. The separate `controls/` Cargo consumer compares the full declared disk
cross-product against actual CLI outputs and independently checks concrete words
and the validator's named mutants. Seven scoped refusal models remain in every
selection: print/startup effects, temporal obligations, fairness, quantified
PROPERTY domains and opaque wrapper contexts receive no agreement/certificate
credit. The fairness-only resident success and wrapper resident refusal remain
actual historical facts, not justification for approximation.

The portable old engine Git-object proof preserves the original producer's
selected source identities without requiring its unmerged Git object in a fresh
checkout. Its current source map is separate from frozen execution evidence.
Neither that proof nor this new role admission authenticates an archive or
certifies a model. The user contract and executable example are in
[the disk safety guide](../../../docs/user/disk-seen-safety.md).
