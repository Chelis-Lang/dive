# Constructive generation controls

These minimal guarded Next actions pin TLC `-generate num=1` before the native
feature is credited. A state-dependent guard prevents TLC's startup action
decomposition from turning the intended runtime disjunction/existential into
separate top-level actions. The pinned oracle is `tlc-2026.10.06.014338`, upstream
`94d0c5070852b37b801bb8998c436383ab7ee37b`.

| Control | Pinned primary observation | Purpose |
| --- | --- | --- |
| GenComplete | finite simulation success, exit 0 | complete samples remain non-exhaustive |
| GenDisj | invariant violation 2110, exit 12, two rows | actual constructive disjunction |
| GenExists | invariant violation 2110, exit 12, two rows | actual constructive bounded existential |
| GenDomains | GENERAL 1000, exit 255, nested division-by-zero 2179 | every source domain evaluates despite an earlier empty domain |
| GenCase | GENERAL 1000, exit 255, UnsupportedOperationException | pinned generator refuses CASE |
| GenPartial | primary incomplete-next 2109, exit 75 | missing variable is an error, never a skipped choice |

Goldens were generated by the harness with a recorded reason. GenPartial has
**no golden**: its required JSON trace pass fails inside TLC's JSON serializer
on the partial state's null binding and leaves an empty file. The harness
correctly refuses to write a golden. The native partial-row regression remains
covered by focused producer/API tests; it is not corpus agreement. GenDomains
and GenCase have known oracle wrapper identities for which native independent
deciding evidence is not owned; they retain explicit unsupported admission.

All six manifests select finite Simulate plus the `constructive generation`
feature. That feature is rejected outside Simulate. Simulation counts and draw
sequences are not general parity gates (ADR 0116); these deterministic violations
and finite completion controls retain their actual report and witness checks.
Raw invocations are regenerated through the harness and are not committed.
