# TLCGet("config") records

These probes pin the record `TLCGet("config")` returns in each TLC run mode
(issue #1249). Each module asserts the record's domain and its
run-independent values in `ASSUME`s, so the golden's verdict is `success`
only when the record matches. The worker count, install location and
fingerprint polynomial are not asserted. The pinned oracle is
`tlc-2026.10.06.014338`, upstream `94d0c5070852b37b801bb8998c436383ab7ee37b`.

| Probe | Harness mode | Asserted |
|---|---|---|
| CfgCheck | exhaustive | `mode` `"bfs"`, `deadlock`, `seed`, `fingerprint`, `worker`, `install` |
| CfgSimulate | `-simulate num=3`, `CHECK_DEADLOCK FALSE` | `mode` `"simulate"`, `traces` 3, `depth` 100, `aril` `"0"`, `sched` `"random"`, `deadlock` FALSE, no `fingerprint` |
| CfgGenerate | `-generate num=2` | `mode` `"generate"`, `traces` 2, otherwise as CfgSimulate with `deadlock` TRUE |

Records printed by the pinned TLC with `ASSUME PrintT(TLCGet("config"))`
(install location elided):

| Command line | Record |
|---|---|
| (none) | `[install, mode \|-> "bfs", deadlock \|-> TRUE, seed \|-> "<random>", fingerprint \|-> "<random>", worker \|-> 1]` |
| `-workers 4` | as above with `worker \|-> 4` |
| `-deadlock` | as above with `deadlock \|-> FALSE` |
| `-dfid 3` | the model-checking record, `mode \|-> "bfs"` |
| `-simulate num=3 -depth 7 -seed 5` | `[install, mode \|-> "simulate", deadlock \|-> TRUE, seed \|-> "5", worker \|-> 1, traces \|-> 3, depth \|-> 7, aril \|-> "0", sched \|-> "random"]` |
| `-simulate num=3 -depth 7 -seed 5 -aril 2` | as above: `aril \|-> "0"` |
| `-simulate num=3 -depth 7 -workers 4` | `worker \|-> 4, traces \|-> 12` |
| `-simulate num=3` | `traces \|-> 3, depth \|-> 100` |
| `-simulate -depth 3` (no `num`) | `traces \|-> -1` |
| `-generate num=3 -depth 7 -seed 5` | as `-simulate` with `mode \|-> "generate"` |

`traces` is `(int) (workers * num)` (`Simulator.createConfig`), so an
unbounded run reports `-workers`. `aril` is `"0"` because the record is
built before `-aril` is applied. dive's handling is D-045 in
`docs/tlc-differences.md`. Goldens were generated by the harness with a
recorded reason; raw invocations are regenerated and not committed.
