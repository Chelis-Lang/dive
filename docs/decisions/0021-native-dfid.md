# ADR 0021: Native depth-first iterative deepening

- Status: Accepted
- Date: 2026-10-10

## Context

The pinned TLC has a separate DFID engine, `DFIDModelChecker`, `DFIDWorker`
and `FPIntSet`. Its visitation contract cannot be reproduced by running BFS
with a depth cap, or by rerunning a plain bounded DFS. Fingerprints carry the
iteration of discovery, a permanent done bit and an alternating iteration
completion bit. Initial-state duplicates count as generated, but only unique
in-model roots are retained.

TLC's `-dfid N` argument is a maximum iterative level, despite help describing
an initial depth. The pure infinite counter `DfidBound`, at levels 2 and 4,
exits zero after 2/2 and 7/4 generated/distinct respectively, without the
completion message 2193. Levels 0 and 1 run only initialization and exit 255.
A zero exit alone cannot establish exhaustive exploration.

Each `DFIDWorker` constructs a fresh Java `RandomGenerator`, calls its own
`nextLong()` and reseeds itself. CLI seed/aril are not used for this selection
stream. The clean `DfidBranch` control produces both `0,1,3` and `0,2,4`
counterexamples with the same supplied seed 7, aril 3 and fingerprint index 0.

## Decision

Implement a native iterative visitation engine inside `dive-check`, sharing
binding, evaluator, canonical state codec and fingerprinting with the checker.
No crate dependency edges change. Keep `dive-trace` independent of both engines.
Expose a separate DFID API/report and explicit CLI mode; do not change the
existing BFS defaults or its conformance gate.

Retain TLC's initial ordering, per-action eager successor generation,
constraint-before-newness decision, invariant/action-property checks, duplicate
counts, random swap-removal of completed roots and successors, status updates
and iteration completion rules. Refuse unimplemented mode interactions by name.

Report a depth-bound stop as incomplete, retaining actual counts, iteration,
workers and seeds, with `exhaustive: false` and `model_proved: false`. TLC mode
retains its measured exit status (including zero at a reached bound), while
dive's default gives an explicit incomplete disposition. Completion must have
a visitation certificate, not merely an exit status or exhausted loop.

Dive's default derives replayable worker streams from the reported seed.
TLC mode retains fresh per-iteration worker selection seeds, reports them, and
records that the CLI seed did not seed those workers. A replay override supplies
those actual worker seeds and is labelled as an override rather than pure TLC.
Curated clean-oracle controls certify deterministic observations; any seeded
worker instrumentation is separate secondary evidence and never pretends to be
the unmodified primary oracle.

Independently validate every claimed violation. Missing witness interpretation
or undecidable validation remains unsupported; rejected witnesses are internal
errors. Resource/depth/collision failures preserve partial evidence and cannot
be safe verdicts. Implement bounded pure safety first; liveness, effects,
continuation, checkpointing, symmetry and additional widths remain explicit
limits until their complete contracts are built.

## Evidence

Clean oracle controls are generated by
`crates/dive-check/tests/fixtures/dfid/capture.py`, with jar/source/JRE identity,
complete selections and raw transcripts. The mode matrix includes initial
and action-vector error precedence, duplicates, roots, cycles, constraints,
deadlock, empty/no-action models, invalid widths/liveness and fixed-seed repeats.
These observations do not yet certify F-025.

The [independent review](../reviews/2026-10-10-native-dfid.md) records the
captured-operator finding, its fix and the separate graph/witness/resource
controls. Full family acceptance remains audit-required.

The native core runs inline; `dfid_file` provides the recommended-stack worker
thread. Modeled live checker state, effects, temporal checks, symmetry, VIEW,
ALIAS, postconditions, continuation, checkpoints and initial/action-property constraint witness
interactions are staged refusals. Raw TLC display and DFID collision probability
text remain outside the current matching claim. The status map uses exact
canonical encodings to detect fingerprint collisions, so a collision cannot
silently remove reachable states. Candidate retention, generated states, map
size and witness depth each have a fixed configurable bound.

Preflight follows configured redirects, lazy expression contexts and actual
enumerated action contexts without forcing them. Opaque operator arguments,
captured functions/sets, unresolved contexts and every checker-state read are
named refusals in this slice. A caller cannot bypass this proof by replacing a
public predicate or action with a hidden effectful capture.

A first deciding successor failure stops the outer root loop, but TLC's inner
DFS continues draining. The native port retains the first witness and reproduces
those counted expansions. This distinction is measured by `DfidBranch`: stopping
immediately would yield 6 generated / 4 distinct instead of TLC's 7 / 5.

For D-019, native traces show the concrete path and are independently certified.
TLC's malformed display is preserved as raw reference evidence, not claimed as a
valid witness or silently emitted by `--compat=tlc`. Matching that legacy display
is a named unsupported option until it has a separate uncertified representation.
