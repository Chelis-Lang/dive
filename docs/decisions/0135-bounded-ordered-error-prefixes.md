# 0135: Bounded ordered error prefixes and source-final VIEW witnesses

- **Status:** accepted; the version-6 writer requires advance consumer notice before landing
- **Date:** 2026-11-01

## Context

Six retained VIEW errors stop while constructing the key of a generated
candidate. TLC's word ends at that candidate's source. Native version 4 instead
requires its final complete row to be the failing candidate, and its site
vocabulary is closed. Reusing that payload would change an existing meaning.
Two named invariant-error words already use version 2 correctly, but word
validity does not establish the different deciding diagnostic error. The
independent ordered driver previously refused every unproved global-newness
claim. Top-level non-Boolean constraint results additionally need the actual
`Tool.isValid` boundary, rather than an invented inner-expression exception.

## Decision

Reconstruct a private finite prefix from immutable source/configuration on a
fresh runtime: exactly one exhausted, admitted Init emission, the complete
expansion of that initial source, and the first admitted noninitial source.
Execute its actual primary event and retain the independently computed
insertions into actual per-action diagnostic generation and checking. No
producer seen set, selected candidate, ordinal, cached truth or checker callback
is an input. There is no general BFS queue or checker/store dependency.

The admitted scope is complete scalar states and scalar/tuple VIEW keys, with
at most 64 key nodes, tuple depth eight, 64 admitted keys and 256 emissions.
Reservations fail through the resource channel; original host controls remain
installed. A bound excess explicitly refuses. Key construction preserves ordered
constraints, required concrete normalization, VIEW evaluation, fingerprinting,
insertion and new-state invariant checking. Fingerprint collisions between
structurally different keys refuse. The run context determines the polynomial;
standalone sessions without that metadata refuse the admission proof. Symmetry,
ALIAS, temporal obligations, effects, additional initial emissions, later source
rows and unproved value-method receiver lifetimes remain unsupported.

Use the shared model's Boolean-role boundary after an actual returned
non-Boolean: it constructs source-qualified `TLC_EXPECTED_VALUE` with the tool's
actual exception provenance. Existing candidate version 4 already expresses
constraint/action-constraint failures and both independently executed exception
identities; its shape and meaning are unchanged.

Introduce native trace version 6 for the closed `view-source-terminal` endpoint.
Its complete rows end at the original source. The absent generated candidate is
reconstructed, never appended or selected by metadata. The endpoint contains
only original source module/span/instance and untrusted reported/deciding codes;
`ending.ec` remains the underlying primary error. Actual typed execution, not a
serialized constructor or proof flag, establishes exception provenance. Existing
native versions 1–5 retain their readers and meanings. Outer report schema 3
is unchanged. Unknown versions/stages and old-version use of the new endpoint
fail closed. Known consumers must receive advance notice and update readers
before advancing an immutable producer pin; the lead records that notice before
landing the writer.

Named invariant words retain version 2. A separate, nonserialized
`InvariantErrorClass` can only be constructed by fresh bounded primary and
diagnostic execution, after ordinary word validation. Source-bound report
mapping and the conformance word check independently require that execution
before accepting a different diagnostic identity. A producer verification flag,
ordinary word validity or a report-header allowlist supplies no certificate.
Unproved producer reconstruction returns unsupported without a formal word or
verified TLC class, retaining the actual search facts and observed primary.

## Consequences

The six VIEW fixtures and two non-Boolean constraint fixtures can share one
ordered execution mechanism rather than fixture-specific rules. The two
invariant fixtures gain independent diagnostic proof without a wire migration.
Their canonical pinned streams remain Unclassified: context2103 and physical75
alone do not uniquely establish deciding2103, and physical255 remains ambiguous.
Word validity, independently proved report identities, strict engine shadows and
pinned-TLC agreement remain separate results. No golden or oracle classifier is
changed by this decision, and no whole-census or milestone acceptance follows.

Negative controls retain old anonymous words, wrong names/causes/source spans,
changed candidates and diagnostic failures, first-false constraint order,
missing primary failures, unsupported normalization/shape demand, source-order
changes, bounds, effects and interrupted validation.
