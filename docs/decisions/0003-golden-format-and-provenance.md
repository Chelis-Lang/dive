# 0003: Golden format, provenance and oracle invocation

- **Status:** accepted
- **Date:** 2026-10-08

## Context

Soundness contract rule 6: golden results are generated by the harness from a pinned oracle, never edited, and regenerated only with a recorded reason. ADRs 0002, 0004 and 0005 fix the oracles, worker counts and corpus metadata. What remained open:
- the on-disk format of a golden;
- what a golden must record so a reviewer can reproduce it;
- how TLC and SANY are invoked so results are stable;
- how results are classified.

Evidence gathered while building the harness (fixtures under `crates/dive-conformance/tests/fixtures/`):

- **Exit codes cannot classify alone.**
  - TLC exits 255 both for crashes and for integer overflow (`TLC_MODULE_OVERFLOW` is not in `EC.ExitStatus.errorConstantToExitStatus`).
  - Action-property violations exit 13, like liveness violations.
  - Parse and semantic errors both exit 150 with the same message code (3002), and are told apart only by SANY's untagged text.
- **Nondeterminism.**
  - TLC picks a random fingerprint polynomial (`fp`) per run, and a random seed. The seed matters in exhaustive search too: `RandomElement` and the `Randomization` module draw from it. Examples `SpanTreeRandom` gave 40460, 1878, 240806, 65396 and 106664 distinct states without `-seed`, and 79550 twice with `-seed 0`.
  - Multi-worker runs that stop at a safety violation stop at a scheduling-dependent point: DieHard gives 14/73/depth 7 with one worker and 16/84/depth 9 with four, and the counterexample length is unchanged.
  - With four workers, TLC also named a different set of violated temporal properties (`MCDistributedReplicatedLog`: "AllExtending and InSync" instead of "InSync"). See the ADR 0004 amendment for how multi-worker TLC runs are reported.
  - Simulation is not reproducible even with `-seed 0` and one worker. Generated-state counts varied between runs, while the verdict and trace length did not.
- **Version differences between the pinned oracles.**
  - v1.7.4 lacks `-dumpTrace`, `-noGenerateSpecTE` and SANY's `-error-codes`, which it rejects.
  - It omits the search depth after assertion, evaluation, overflow and liveness errors.
  - It does not name the violated temporal property ("Temporal properties were violated.").
  - It nests a complete `-tool` message inside `GENERAL` (1000) for configuration errors, for example the `ALIAS` keyword, which it does not know.
- **Resource exhaustion depends on the machine.** Out-of-memory and stack-overflow outcomes depend on `-Xmx`, `-Xss` and the JVM.
  - 94d0c50 at `-Xmx64m` reports `SYSTEM_OUT_OF_MEMORY_TOO_MANY_INIT`.
  - On the same spec, v1.7.4 refuses a set with more than 1,000,000 elements instead.
  - A deep recursion reports `GENERAL` ("StackOverflowError") followed by the context code 2103.
- **Oracle runs write into their working directory.** Examples animation specs write SVG files; 125 were already in the cache. Examples' `.gitignore` ignores almost everything, so `git status` without `--ignored` missed them.
- **Spec output can contain marker text.** `PrintT("@!@!@ENDMSG 2185 @!@!@")` is printed quoted and mid-line.
- **SANY exit codes.** SANY exits 0 on semantic errors unless given `-error-codes` (which `94d0c50` supports and v1.7.4 rejects).
- **CommunityModules and v1.7.4.** Every CommunityModules release tried (202610040242, 202405171516, 202010302007) makes v1.7.4 fail on every spec with `NoClassDefFoundError`/`IncompatibleClassChangeError`. `tlc2.overrides.TLCOverrides` references classes that v1.7.4 lacks, because v1.7.4 branched from upstream master on 2020-04-25.
- **Module libraries.** Upstream Examples CI puts the TLAPS library (tlapm `library/`) and Apalache's modules on the classpath. About 71 Examples modules `EXTEND` TLAPS-library modules and cannot be parsed without them.

## Decision

**Location.**
```text
conformance/golden/<oracle-id>/<corpus-id>/<model-path>.json         TLC, one per model
conformance/golden/<oracle-id>/<corpus-id>/sany/<module-path>.json   SANY, one per module
```
Paths keep the corpus-relative directory structure. Bytes outside `[A-Za-z0-9._-]` are percent-encoded, so the mapping is injective. Generation also refuses two inputs whose golden paths collide case-insensitively.

**Format.**
- Pretty-printed JSON with a fixed key order (struct order; JSON objects inside, such as the trace, use sorted keys) and a trailing newline.
- Top-level keys: `schema` (1), `kind` (`tlc-model` or `sany-module`), `oracle`, `corpus`, `model` or `module`, `workers` (always 1), `result`, `provenance`.
- Every golden struct is read with `deny_unknown_fields`, so a renamed field is an error rather than a silently missing value.
- Everything except `provenance` is the **payload**. It is deterministic: no timestamps, timings or machine paths. Only the payload is ever compared, and regeneration with an unchanged oracle and corpus reproduces it byte for byte.
- The TLC `result` is the typed `OracleResult`:
  - the verdict class;
  - the deciding message code and its `EC` name;
  - the exit code and its `EC.ExitStatus` name;
  - the violated property where TLC names it;
  - distinct/generated/queue counts and depth;
  - the fingerprint collision probabilities as printed;
  - the counterexample;
  - all error and warning codes, unresolved modules, and a note.
- **Simulation counts** are not reproducible: TLC's generated-state count varies between runs even with `-seed 0` and one worker. For simulation models they are moved out of the payload into `provenance.uncompared_counts`.
- **Counterexamples** keep the `-dumpTrace json` document verbatim, or, for oracles without `-dumpTrace` (v1.7.4), the states from the message stream. Content whose canonical JSON exceeds 1 MB is replaced by its length and SHA-256, with the reason recorded.

**Provenance.**
- Oracle id, jar SHA-256, upstream commit, and the jar's `X-Git-Revision` and `Implementation-Version`.
- Classpath jars and module libraries with their pins.
- Probed capabilities.
- Java: the pinned JRE's version, archive SHA-256 and platform, or the explicit `--java` path and its SHA-256.
- Corpus commit.
- The exact command line, with `$DIVE_CACHE_DIR`, `$TMP` and `$CWD` placeholders.
- The timeout, the `--reason`, the `dive-conformance` version, and the generation timestamp and elapsed time.

**Overwrite rule.** The harness refuses to overwrite an existing golden without `--reason "<text>"`. It reports whether the payload changed. Hand edits are never acceptable.

**Run-time consistency checks.** A run refuses to compare, reporting `oracle-error`, when any of these hold:
- the golden's corpus commit or jar SHA-256 differs from the current pins;
- the manifest entry it describes has changed;
- the golden itself is `oracle-error`, `unclassified` or `timeout`.

This applies to SANY goldens too, including the jar SHA-256 check. A selected module or model without a golden is reported as `oracle-error`; it never vanishes. Every selected model and module gets exactly one outcome, and the report's summary asserts that the totals equal the selection.

**Invocation.**
- **Upstream Examples CI** is mirrored: working directory, `-XX:+UseParallelGC`, `-lncheck final -cleanup`, `-Dtlc2.tool.impl.Tool.cdot=true` for `action composition`, deadlock checking left at TLC's default, and `-simulate num=N` in simulation.
- **Additions:**
  - `-tool`;
  - `-workers 1`;
  - `-fp 0` and `-seed 0`, always (both modes; v1.7.4 accepts `-seed` in breadth-first mode, which the capability probe confirms);
  - a unique `-metadir`;
  - `-dumpTrace json` where supported, only in a separate trace pass since issue #35 (see the amendment below);
  - a configurable `-Xmx`, and `-Xss8m` pinned so deep recursion behaves the same on every machine;
  - a pinned JVM locale, encoding and temporary directory.
- **Telemetry and TE specs:**
  - The harness does not copy upstream's `-Dutil.ExecutionStatisticsCollector.id`, which reports usage under upstream CI's identifier.
  - TLC's `user.home` is a harness directory whose `.tlaplus/esc.txt` opts out of statistics collection.
  - `-noGenerateSpecTE` is not passed: v1.7.4 rejects it, and in `94d0c50` `-tool` already disables trace-exploration specs.
- **Capabilities** are probed per oracle and recorded, so missing features show up as data.
- **Isolation:** every TLC and SANY job runs in a fresh scratch copy of the spec directory (for Examples, `specifications/<spec>/`, which no spec reaches outside of), so nothing a spec or TLC writes can reach the cached corpus.
- **Integrity:** after every oracle run the harness checks that the corpus checkout is unmodified, using `git status --untracked-files=all --ignored`.
- **Timeouts:** the derived timeout is `20 × manifest runtime + 120 s`, at least 300 s and capped by `--timeout-cap`. Once a golden exists, it is also at least `4 × golden elapsed + 60 s`, which may exceed the cap. Manifest runtimes were measured with several workers: Examples `BufferedRandomAccessFile` records 9 s but took 102 s with one worker.

**Classification.**
- The `-tool` stream decides; the exit code cross-checks. The rules are in `crates/dive-conformance/src/tlc/result.rs`.
- An exit code that no error message explains is `oracle-error`, with both recorded.
- An unknown exit code or message code, or a malformed stream, is `unclassified`, with the raw data kept. So is an exit code that only a context message (2103, 2121, 2264) explains.
- **Resource limits.** JVM resource exhaustion is `resource-limit`, which is never an oracle fact and never written as a golden. It covers:
  - `SYSTEM_OUT_OF_MEMORY*` (1001–1003) and `SYSTEM_STACK_OVERFLOW` (1005);
  - `GENERAL` naming `OutOfMemoryError` or `StackOverflowError`;
  - either name on stderr.
- **Other oracle errors.** These turn a would-be fact into `oracle-error`, with the stderr kept:
  - a success without state statistics;
  - any stderr line outside a narrow allowlist. The allowlist currently holds only v1.7.4's resolver diagnostic `File does not exist: ...`; normal runs print nothing on stderr.
- **Markers are positional.** Message markers count only where TLC prints them: a `STARTMSG` header followed by a newline, and an `ENDMSG` at the start of a line. Marker text inside spec output is ordinary text.
- **2108.** `TLC_PROPERTY_VIOLATED_INITIAL` (a state-predicate `PROPERTY` violated by an initial state) is a `safety-violation`. TLC exits 13 for it, as for liveness, but the counterexample is one initial state.
- SANY accepts a module only if it exits 0 *and* prints no error marker. A `Semantic errors:` header alone is not a marker: v1.7.4 prints it above warnings-only lists. Only `*** Errors:`, `*** Abort messages:` and the parse markers count.

**Classpath per oracle.**
- Each `[[tlc]]` lists its classpath jars. `94d0c50` gets CommunityModules 202610040242; v1.7.4 gets none.
- `[[module_library]]` pins the TLAPS library (tlapm `d8b9747`) and Apalache's modules (v0.62.3), fetched with git at a pinned commit, for every oracle. This amends ADR 0002.

## Consequences

- **Payload diffs are meaningful.** A golden diff in review is a real change in oracle output, since provenance noise is confined to one object.
- **v1.7.4 is a weak cross-check.** Specs that need CommunityModules fail to parse on v1.7.4, which shows up as cross-oracle disagreement. Its main value is detecting drift in core TLC semantics.
- **The Examples manifests are not authoritative.** They were recorded with an unpinned TLC and unpinned module libraries, so drift against them is reported but never counted as disagreement (ADR 0005).
- **Upstream changes need harness updates.** When upstream changes its message texts (property names, SANY markers), the fixtures fail first.
- **Revisit:**
  - when a pinned oracle moves (regenerate `EC_CODES` and the exit mapping, and re-capture fixtures);
  - if a CommunityModules release compatible with v1.7.4 is found;
  - when `dive` produces verdicts and needs its own error-class vocabulary.

## Amendments

- **2026-10-08 (issue #16).**
  - **Outcome.** Reports gain the outcome `known-upstream-change`. A TLC oracle under test gets it for a difference from the golden that entries in `conformance/oracle-changes.toml` fully explain (ADR 0002). Like `expected-divergence`, it is never counted as `agree` and is not a finding. Unexplained differences stay `disagree`.
  - **Report fields.** Reports record `golden_oracle_role`, `implementation_oracle_role` and `reference`. A run involving a reference oracle does not gate.
  - **Compatibility.** The golden format is unchanged, and no golden or report was regenerated. The new report fields default when older reports are read.
- **2026-10-08 (dive's front end in the harness).**
  - **Parse-phase verdicts need no new goldens.** `run --sany-phase parse` compares `dive parse` with SANY's parse-phase verdict of each module's own file (`accept`, `name-mismatch`, `reject`). That verdict is derived from the existing full-SANY goldens, with no `-s` goldens. This is sound for two reasons. First, SANY parses the root file first and aborts at the first parse-phase failure. Second, `error_text` keeps SANY's text from the first error marker on, including its attribution line (`Could not parse module <M> from file <F>`, `File name '<M>' does not match ...`). A golden whose text does not determine the verdict is `oracle-error`, never a guess.
  - **Module corpora.** `modules-only` corpora take `include` globs and `[[corpus.exclude]]` entries (path and reason). Excluded modules have no golden and are reported as `out-of-scope`. A module that crashes SANY (an internal exception, with no error marker) is excluded this way, because its result is not an oracle fact. For modules outside an Examples spec directory, isolation copies only the files of the module's own directory, since SANY never searches subdirectories.
  - **Reports.** Reports gain `implementation_dive`, `settings.sany_phase`, `summary.by_corpus` and, per module, `phase`, `golden_parse_verdict` and `parse_verdict`. A run can cover several corpora.
  - **Compatibility.** The golden format is unchanged, and no existing golden was regenerated. The new report fields default when older reports are read.
- **2026-10-08 (issue #35: goldens from unperturbed TLC).**
  - **The problem.** `-dumpTrace json` is not a passive output flag. `ParameterizedSpecObj` adds `_JsonTrace` as an extendee of the root module, and `_JsonTrace` loads `TLC`, `TLCExt`, `Json`, `Sequences`, `FiniteSets`, `Naturals` and, through `TLCExt`, `Integers`. Their Java overrides are then installed, and `Integers`' replace `Naturals`' on the definitions they share, even in a spec that extends only `Naturals`. Measured on the pin: `"a" >= 1` reports `>=` instead of `Naturals.GEQ`'s `>`; `-2147483648 \div -1` overflows instead of wrapping; and `(0 - 1) \div 2` is `-1` instead of `Naturals.Divide`'s `0` (fixtures `ErGeqNaturals`, `ErPlusNonIntNaturals`, `RvNatDiv`). The extra modules are also lexed, which can move names in TLC's intern order. So goldens recorded TLC as perturbed by the harness, not as users run it (charter rule 1).
  - **Flag audit.** Every flag the harness passes to TLC and SANY was checked at `94d0c50`; the table is in the harness README ("Oracle invocation: flag audit"). Only `-dumpTrace` perturbs. `-workers 1` is TLC's default; `-fp 0`, `-seed 0`, `-lncheck final`, the classpath and `-Dtlc2.tool.impl.Tool.cdot=true` are chosen settings that users can also choose; the rest (`-tool`, `-cleanup`, `-metadir`, `-Xmx`, `-Xss`, `-XX:+UseParallelGC`, the system properties, SANY's `-error-codes`) are inert. SANY is never given `-dumpTrace`, so SANY goldens were never affected.
  - **Options considered.**
    - **(a) No `-dumpTrace` at all:** rebuild the JSON document from the `-tool` stream (2217 states, 2121/2122/2218 for how the behaviour ends) by parsing TLC's printed values. Rejected, because the document holds two things the stream does not show. First, `vars` is a TLA+ set of variable names serialized in TLC's normalized order, which for strings is intern-token order (`UniqueString.compareTo`), not the declaration order in which states are printed. In `MCRealTimeHourClock` the stream prints `now`, `hr`, `t` and the JSON has `["now", "t", "hr"]`. Reproducing that needs SANY's full intern sequence, which ADR 0012 records as an open task. Second, an action with parameters carries `context` and `parameters` keyed by the formal parameter names, while the stream's label prints only their values (`<Extend(n2) line ...>`). An exact round trip is therefore infeasible today.
    - **(b) Two runs (chosen).** A clean run without `-dumpTrace` decides the verdict, deciding code, exit code, violated property, counts, collision estimates, error and warning codes, and the counterexample's printed states. Only when it ends with a counterexample (one worker, an oracle with `-dumpTrace`) does a second *trace pass* run with `-dumpTrace json`. Its JSON is used only if its own message stream reproduces the clean run's verdict, deciding code, violated property and trace exactly: the same length, ending, and every state's label and printed value, byte for byte. Otherwise the result is `oracle-error`, naming the difference, and no JSON is kept. The JSON's state count is then checked against the clean stream, as before. This is stronger than the issue's "verdict and trace length agree": a trace pass that explored differently, or printed any value differently, cannot contribute its document.
  - **Format.** The payload format is unchanged; `json` still holds the `-dumpTrace json` document verbatim. Provenance gains an optional `trace_command`, the trace pass's command line; `command` is the clean run. When TLC writes no JSON (assertion, evaluation and overflow errors), the clean run's printed states are kept in `steps`, as before. `dev capture` follows the same rule and writes `.trace.command`.
  - **Result.** All 141 Examples TLC goldens (the 140-model small tier and `EWD840_anim`) were regenerated with the reason "Issue #35: goldens from unperturbed TLC (no -dumpTrace side effects)". Every payload is byte-identical to the perturbed one: no verdict, count, error, property or trace changed, and the 17 counterexample documents are unchanged. 17 models needed a trace pass, and every one reproduced the clean counterexample. On this corpus the perturbation did not matter. It did matter for the three constant-only fixtures above, which were recaptured, and for probe `StringOrderPreinterned` (`crates/dive-check/tests/fixtures/tlc-probes/`): the extra modules change TLC's intern order, so it reports `InvA` with `-dumpTrace` and `InvB` without. That probe also shows the cross-check working: its trace pass reports `InvA`, so it cannot vouch for the clean run, and the result is `oracle-error` with no JSON. A golden in that position would be refused rather than written with a perturbed document. Recapturing all 292 `dev capture` transcripts without the flag changed nothing else (`Oom` aside, which was captured at `-Xmx64m` and recaptured at the default heap).
