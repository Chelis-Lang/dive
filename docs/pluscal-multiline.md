# Multiline expressions in sequential PlusCal

Native translation admits bounded multiline expressions whose token grouping
is independent of indentation. Arithmetic, tuples, record values, IF/CASE
values, declarations, selectors and changed-variable reads use the same lexical
substitutions as the pinned translator. This applies to sequential algorithms
without macro declarations or procedures. Process-owned expressions, macro
substitution, TLA binders and multiline junction lists remain named refusals.

Save this P-style source as `Multiline.tla`:

```tla
---- MODULE Multiline ----
EXTENDS Integers
(* --algorithm A
variables x = 0, y = 0;
begin
  Start: x := 1;
         y := x +
              2;
  Finish: skip;
end algorithm; *)
====
```

Its C-style counterpart is:

```tla
---- MODULE Multiline ----
EXTENDS Integers
(* --algorithm A {
  variables x = 0, y = 0;
  {
    Start: x := 1;
           y := x +
                2;
    Finish: skip;
  }
} *)
====
```

Both produce an action containing `x' = 1` and `y' = x' + 2`. This is a
read-after-write substitution in one action, not an extra state transition.
Comments, blank expression lines, tabs and UTF-8 comments can remain in the
source; LF and CRLF inputs are supported. Generated expression trivia may be
normalized. Exact primary pretty-print bytes and mapping-format parity are
pending; operator tree equality is checked independently of whitespace.

Run either module without overwriting it:

```sh
dive translate Multiline.tla --rewrite --compat=tlc --output json > plan.json
```

The admitted report has `result: "replacement"`, both reference CRC derivation
flags true and the module under `replacement.module_source`. `model_proved` and
`exhaustive` are false: translation is not model checking. The source file is
unchanged. The default profile preserves its newline convention; TLC mode
normalizes LF. Explicit `--checksums tla` disables the algorithm CRC, records
only the body CRC and labels a TLC run `tlc+overrides`; it never silently replaces
an unsupported Full request. Under `--fair algorithm`, the pinned algorithm
CRC hashes only `fair` (D-020), so matching CRCs do not prove source identity.

The public API follows the same admission contract:

```rust
use dive_api::{RewriteRequest, rewrite_source};
let source = std::fs::read_to_string("Multiline.tla")?;
let report = rewrite_source("Multiline.tla", &source, &RewriteRequest::default());
assert!(report.accepted());
assert_eq!(report.to_json()["model_proved"], false);
println!("{}", report.to_json());
# Ok::<(), Box<dyn std::error::Error>>(())
```

A maintained Cargo-owned executable runs this path:

```sh
cargo run -p dive-api --example pluscal_multiline -- Multiline.tla
cargo run -p dive-api --example pluscal_multiline -- Multiline.tla --body-only --compat=tlc
```

For an indentation-sensitive example, replace the assignments with:

```tla
Start: await /\ TRUE
             /\ x = 0;
```

This returns exit 3 with `Unsupported` and an original byte span naming multiline
junction layout. Flattening those lines could change which conjunct belongs to
which expression. Bindings such as `CHOOSE`, quantifiers, LET and function/set
binders, multiline expressions in macros/processes/procedures and bare-CR layout
also refuse. Valid empty-THEN branches retain their named generation refusal;
malformed TLA expressions and invalid reference artifacts receive no successful
admission credit. No implicit fallback runs Java or emits an unchecked artifact.

Source limits remain 1 MiB, 100,000 tokens, 50,000 parsed/normalized nodes and
depth 128, with hard 4 MiB/depth-256 ceilings. Action counts and generated bytes
remain globally bounded at 10,000 actions / 4 MiB. Caller-lowered output/document
quotas return named `Resource` results, never partial admitted artifacts.

The complete captured selection and controls live in
`crates/dive-pluscal/multiline-acceptance/`. It retains the unchanged generator's
refusals, clean primary transcripts, post-Explode ASTs, rejected and invalid
primary artifacts, exact significant operator CST comparisons, SANY and
Full/body-only Validator checks. Finite state-count and independently validated
witness controls are separate evidence, not full translator certification.
See [rewrite contracts](pluscal-rewriting.md), [AST checksum scope](pluscal-checksum-expressions.md)
and [the design](decisions/0047-bounded-translation-block-editing.md).

The final selection contains 208 immutable sources: 130 admitted artifacts per
profile and per checksum policy, 34 named refusals, 20 primary parser rejections
and 24 primary translator outputs rejected by SANY. The latter receive no
admission credit. Each policy has 260 native SANY/Validator and strict
whole-module CST controls. Twelve Full and six body-only source/body/header
corruptions retain the measured reference dispositions; 37 forged Full and 35
forged body-only reports are rejected. The old weak body-only comparator and
its three accepted forgeries remain visible as failures.

Twenty-eight finite safe/violating generated models match the clean primary's
counts at 1/4/8 workers in both profiles and both fingerprint/exact stores
(336 controls). Fourteen TLC-profile counterexamples independently validate;
56 deliberately broken witnesses do not. This includes CASE branches whose
arrow must trigger enclosing parentheses: the previous 16 significant-tree
mismatches are preserved before the repair. Twenty CLI/Cargo-owned API guide
controls and 512 lowered-byte/span controls are separate qualified evidence.
None of these results certify the full PlusCal grammar, formatter or F-034.
