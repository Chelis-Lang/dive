# Full checksums for a finite process calling a procedure

The bounded editor derives TLC's algorithm-header CRC for one explicitly labelled,
unfair finite process and one procedure with disjoint names. Both C and P syntax
are supported. The header is finite source data; recursion is not unrolled and a
successful replacement neither proves termination nor validates a model witness.
The global parser, action, expansion, byte and depth limits are unchanged.

Save this runnable P example as `ProcessHeader_P_member_parameter.tla`:

```tla
---- MODULE ProcessHeader_P_member_parameter ----
EXTENDS Integers, Sequences, TLC
(* --algorithm A variables x=0;
procedure First(a=0) begin F:x:=a; R:return; end procedure;
process Worker \in {1,2} begin L:call First(2); E:skip; end process;
end algorithm; *)
====
```

The equivalent C comment is:

```tla
(* --algorithm A { variables x=0;
procedure First(a=0) { F:x:=a; R:return; };
process (Worker \in {1,2}) { L:call First(2); E:skip; } } *)
```

```sh
dive translate ProcessHeader_P_member_parameter.tla --rewrite --output json
dive translate ProcessHeader_P_member_parameter.tla --rewrite --compat=tlc --output json
cargo run -p dive-api --example pluscal_process_procedure_checksum -- ProcessHeader_P_member_parameter.tla
```

The Cargo-owned executable calls the public API:

```rust
use dive_api::{RewriteRequest, rewrite_source};
let source = std::fs::read_to_string("ProcessHeader_P_member_parameter.tla")?;
let report = rewrite_source("ProcessHeader_P_member_parameter.tla", &source, &RewriteRequest::default());
assert!(report.accepted());
println!("{}", report.to_json());
# Ok::<(), Box<dyn std::error::Error>>(())
```

An admitted report has `result: replacement`, verified algorithm/body CRC
derivation and `replacement.module_source`. It also reports `model_proved: false`
and `exhaustive: false`. The paired C/P member example has reference algorithm
CRC `d3c8177`; replacing the member declaration with `Worker=1` has CRC
`39337b95`. CRC equality is reference derivation equality, not proof of source
identity, execution completeness or safety. `--checksums tla` selects body-only
editing; the Cargo example accepts `--body-only`. Both profiles implement the same
supported checksum semantics; overrides report `tlc+overrides` where applicable.
The editor returns replacement data and does not write the input file.
`-nof` selects no fairness explicitly; the separately captured 56 `-nof` settings
on the same candidate sources produce exactly the same pinned generated bytes,
original stored AST and header CRC as their declared/unfair settings. Other
fairness options remain refused in this Full scope.

The stored header keeps each procedure's source-owned called vector and each
process's separate vector. A process calling First does not add First to the
last procedure's vector: the sequential LAST/main alias does not apply.
Parameter/local/frame fields in the original stored AST remain unindexed.
Generated TLA separately indexes `pc`, `stack` and procedure storage by `self`
or the actual constant process ID. Call/return saves and restores those slots;
local initializers can refer to earlier parameter/local slots. Nested If/With/
Either/While shared-vector mutations and finite source recursion reuse the
proved typed header view. Direct exploded `xast` is separate evidence and is
not the CRC authority.

This Full scope accepts a single literal constant ID or the existing admitted
literal finite member domain, ordinary calls/returns, call-goto, explicitly
labelled control flow, simultaneous arguments, locals, unused procedures and
source-finite self calls. It keeps one process and one procedure, global namespace
admission and the previous per-label assignment restriction. Process/algorithm
fairness, fairness options other than declared/none, label modifiers, multiple
process blocks or multiple procedures, nonliteral domains, scoped renaming,
automatic labels, definitions/macros in this procedure checksum context and
unproved multiline generation remain named Full refusals. Broader raw translation
can be supported while Full editing refuses; neither is a model proof. Unknown
calls, arity failures and reference parser errors retain their actual stages.

A pinned `with a=2 do call First(a)` declaration shadows the procedure slot `a`.
Both clean C/P translators produce TLA that SANY rejects for a duplicate operator.
These reference artifacts remain invalid and earn no replacement/model credit.
The native checksum admission rejects the unproved scoped-name context before
emitting any successful CRC. No upstream invalid artifact is silently corrected.

Strict saved-frame replay still has the #124 namespace limitation. Strict named
Unsupported and canonical-only Valid are separate; a canonical replay never
counts as strict TLC-profile agreement. Translation/CRC equality, whole-module
CST/SANY/Validator admission, finite model counts and replay each have independent
obligations. No general process/fairness or F-034/F-035 certification is claimed.

The declared selection retains all 170 predecessor inputs and adds 72 sources:
56 C/P constant/member candidate positives and 16 boundaries. The first clean
capture exposed 15 C separator errors; every original input/output remains, with
only those exact semicolons corrected in a separate complete 242-row capture.
The corrected new census is 66 generated, 64 SANY-valid, six primary errors and
two generated/SANY-invalid artifacts. Before changes, all 72 new headers were
refused. The frozen implementation matches all 56 candidate headers exactly and retains
every boundary. The complete 242-row raw campaign reports 202 exact header AST/CRC
matches, 26 named refusals, ten accounted rejections, two invalid CLI inputs and
two primary-invalid raw artifacts kept uncredited. Across both profiles, the
484 public routes report 404 exact whole-module CST/SANY/Validator admissions,
48 named refusals, twenty accounted rejections, four invalid CLI routes and
eight primary-invalid routes kept uncredited. The separate `-nof` context adds
56 exact header checks and 112 public admissions on unchanged source bytes.

Finite checking is a different obligation: 154 sources, two configurations each,
and 3,696 profile/worker/store settings match the pinned verdicts and counts.
The 1,540 separate replay controls report 154 canonical-only Valid and 616
canonical Invalid, alongside 462 strict Unsupported and 308 strict Invalid.
**Zero strict saved-frame witnesses receive Valid credit.** These results do
not certify every procedure/process form or imply proof from a translation.
